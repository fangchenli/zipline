Development
-----------

:Release: 2.0.0
:Date: TBD

.. warning::
   This release is still under active development.  All changes listed are
   subject to change at any time.

This release revives Zipline on a modern stack. Zipline 1.4.1 supported
Python 3.6 with pandas 0.22; this release supports Python 3.12, 3.13 and 3.14
with pandas 3, numpy 2, Cython 3 and SQLAlchemy 2. Several behaviours change
as a result; see :ref:`api-changes-2.0.0` before upgrading.

Highlights
~~~~~~~~~~

- Supports Python 3.12, 3.13 and 3.14, and drops support for older versions.
- Supports pandas 3, numpy 2, Cython 3 and SQLAlchemy 2.
- Trading calendars now come from
  `exchange_calendars <https://github.com/gerrymanoim/exchange_calendars>`__,
  which replaces the unmaintained ``trading_calendars``.
- Session labels are timezone-naive dates. Minutes and other points in time
  remain timezone-aware UTC timestamps.
- Zipline ships type information: ``.pyi`` stubs for its Cython extensions and
  a generated stub for :mod:`zipline.api`.

.. _api-changes-2.0.0:

API and Behaviour Changes
~~~~~~~~~~~~~~~~~~~~~~~~~

- Session labels are tz-naive midnight timestamps, e.g.
  ``pd.Timestamp("2016-01-04")`` rather than
  ``pd.Timestamp("2016-01-04", tz="UTC")``. This applies to
  ``SimulationParameters`` start and end sessions, calendar sessions, asset
  lifetime dates (``start_date``, ``end_date``, ``auto_close_date`` and so on),
  daily bar indexes, adjustment dates and pipeline output dates.
  ``run_algorithm``, ``run_pipeline`` and the command line interface still
  accept tz-aware dates and convert them.
- Calendars come from ``exchange_calendars`` through
  :func:`zipline.utils.calendar_utils.get_calendar`, which is also exported as
  ``zipline.get_calendar``. It builds calendars with ``side="right"`` (the NYSE
  trades 9:31 to 16:00) and history back to 1990. Some calendar methods have
  new names; in particular, the first trading minute of a session is
  ``session_first_minute`` / ``first_minutes``, while ``session_open`` /
  ``opens`` are the opening bell.
- ``data.history()`` with several assets *and* several fields returns a
  DataFrame with ``(field, asset)`` MultiIndex columns instead of the removed
  ``pandas.Panel``. ``history(...)[field]`` still gives a dates x assets frame.
- The default bundle is ``massive`` instead of ``quandl``, whose WIKI dataset
  stopped updating in 2018.
- The ``quantopian-quandl`` bundle is removed because the Quantopian-hosted
  mirror it downloaded from no longer exists. ``quandl``, which downloads the
  WIKI Prices dataset from Nasdaq Data Link (formerly Quandl), is now the
  default bundle. It requires a free API key in ``QUANDL_API_KEY``, and the
  dataset ends in March 2018.
- ``BundleData`` (returned by ``zipline.data.bundles.load``) has a ``close()``
  method and is a context manager, releasing its database connections.
  ``run_algorithm`` closes the bundle it loads.
- Pipeline output columns are sorted by name. Categorical pipeline outputs
  whose missing value is ``None`` now show missing values as NaN.
- Multiple-output custom factors used directly as pipeline columns produce
  object columns of tuples instead of numpy records.
- ``zipline.utils.cache.dataframe_cache`` only supports pickle serialization,
  since pandas removed msgpack support.
- The HDF5 minute bar update files written by ``H5MinuteBarUpdateWriter`` use
  format version 1, a frame indexed by ``(sid, dt)``, replacing the
  ``pandas.Panel`` based version 0.
- ``InMemoryDailyBarReader.from_panel`` is removed; pass a dict of frames
  keyed by field to the constructor instead.
- The execution styles' ``get_limit_price`` and ``get_stop_price`` take an
  ``is_buy`` argument on every style; some styles previously called it
  ``_is_buy``.
- ``TradingAlgorithm.portfolio`` and ``account`` raise ``AttributeError`` with a
  clear message when accessed outside of a running simulation.
- A bundle's ingest function now receives a
  :class:`~zipline.data.parquet_daily_bars.ParquetDailyBarWriter` as
  ``daily_bar_writer`` and a
  :class:`~zipline.data.parquet_minute_bars.ParquetMinuteBarWriter` as
  ``minute_bar_writer``. Their ``write`` methods may be called only once, each
  sid may appear only once, and dates must be sessions (daily) or trading
  minutes (minute) of the bundle's calendar.
- The ``minutes_per_day`` argument of
  :func:`~zipline.data.bundles.register` is deprecated and ignored.
- bcolz is no longer a required dependency. Reading bundles ingested by
  earlier versions, whose bars are stored with bcolz, needs the ``bcolz`` extra
  (``pip install 'zipline[bcolz]'``); loading such a bundle warns that bcolz
  support is deprecated and suggests ``zipline convert``. The bcolz minute bar
  classes moved from ``zipline.data.minute_bars`` to
  ``zipline.data.bcolz_minute_bars``; ``zipline.data.minute_bars`` keeps the
  format-neutral ``MinuteBarReader`` base class.
- The HDF5 daily bar format (``zipline.data.hdf5_daily_bars``) is removed;
  store daily bars as Parquet. ``MultiCountryDailyBarReader``, which combines
  one daily bar reader per country, moved to
  ``zipline.data.multi_country_daily_bars`` and now takes any readers that
  provide ``sids``, such as
  :class:`~zipline.data.parquet_daily_bars.ParquetDailyBarReader`.
- FX rates are stored as Parquet: ``HDF5FXRateReader`` and
  ``HDF5FXRateWriter`` are replaced by
  :class:`~zipline.data.fx.ParquetFXRateReader` and
  :class:`~zipline.data.fx.ParquetFXRateWriter`, which take the same data.
  h5py is no longer a dependency, and PyTables is only needed with the
  ``bcolz`` extra.
- Zipline logs through the standard library's :mod:`logging` module instead of
  Logbook, which is no longer a dependency. Loggers are named after their
  modules (e.g. ``zipline.finance.metrics.tracker``), so
  ``logging.getLogger("zipline")`` configures all of them. As is usual for a
  library, Zipline installs no handlers: ``run_algorithm`` shows only warnings
  and errors unless logging is configured, e.g. with
  ``logging.basicConfig(level=logging.INFO)``, while the command line
  interface shows info messages too. Log records no longer carry the
  simulation time as ``algo_dt``. The ``WithLogger`` test fixture and
  ``zipline.testing.make_test_handler`` are removed; use
  :meth:`unittest.TestCase.assertLogs` instead.

Enhancements
~~~~~~~~~~~~

- New Parquet storage format for daily bars,
  :class:`~zipline.data.parquet_daily_bars.ParquetDailyBarWriter` and
  :class:`~zipline.data.parquet_daily_bars.ParquetDailyBarReader`. Bars are
  written as a year-partitioned Parquet dataset that pyarrow, pandas and DuckDB
  can also read directly. Compared with bcolz, pipelines over daily data run
  2-8x faster, daily backtests about 2x faster and writing is slightly faster.
  Bundles ingest daily bars into this format; bundles ingested by earlier
  versions, with bcolz daily bars, still load.
- New Parquet storage format for minute bars,
  :class:`~zipline.data.parquet_minute_bars.ParquetMinuteBarWriter` and
  :class:`~zipline.data.parquet_minute_bars.ParquetMinuteBarReader`. Only
  minutes with a bar are stored, in monthly partitions; prices are stored as
  float64 rather than bcolz's scaled uint32, so there is no rounding to three
  decimals or volume limit, and early closes need no special handling. Minute
  backtests run as fast as with bcolz, and loading minute windows for many
  assets is about 3x faster. Bundles ingest minute bars into this format;
  bundles ingested by earlier versions, with bcolz minute bars, still load.
- New ``zipline convert`` command and :func:`zipline.data.bundles.convert`
  function, which rewrite the bcolz daily and minute bars of bundles ingested
  by earlier versions as Parquet.
- New ``alpaca`` bundle with US equities from `Alpaca
  <https://alpaca.markets>`__ since 2016, with the free API keys of a paper
  trading account: unadjusted daily bars, splits, dividends and asset
  metadata, including acquired and removed securities. Renamed companies
  keep one sid, and later ingestions only download new data. See
  :ref:`alpaca-data-bundle`.
- New ``massive`` bundle, the new default, with US equities from `Massive
  <https://massive.com>`__ (formerly Polygon.io): unadjusted daily bars,
  splits, dividends and asset metadata, including delisted securities, with a
  free API key. Ticker changes keep one sid, reused tickers get new ones, and
  each security keeps its sid across ingestions. Downloaded bars and ticker
  listings are cached, so later ingestions only download new sessions. See
  :ref:`massive-data-bundle`. ``zipline.data.bundles.vendor`` has the parts
  that don't depend on the vendor, for writing other such bundles.
- Backtest results can be saved as Parquet: ``zipline run -o`` writes Parquet
  when the file name ends in ``.parquet`` (other names are still pickled), and
  :func:`~zipline.utils.results.write_results` and
  :func:`~zipline.utils.results.read_results` save and load the results of
  ``run_algorithm``. Unlike pickles, the files don't depend on the pandas
  version and other tools can read them; in the ``orders``, ``transactions``
  and ``positions`` columns, assets are stored as sids and order statuses as
  their names.

Bug Fixes
~~~~~~~~~

- The ``csvdir`` bundle can ingest a directory with both ``daily`` and
  ``minute`` files; it used to fail writing the asset database twice. Each
  symbol gets one sid across both, its lifetime spans all of its bars (as
  sessions, also for minute-only data), and splits and dividends are read from
  one time frame only. Files are matched to symbols by name rather than by
  substring, which could give the symbol ``PL`` the file ``AAPL.csv``.
- Daily bars resampled from minute bars (e.g. futures' daily history) summed
  volume in uint32, which overflowed for sessions with more than 2 ** 32
  shares or contracts traded.
- ``InMemoryDailyBarReader.get_value`` and ``get_last_traded_dt`` used a
  misnamed attribute and always raised; ``get_last_traded_dt`` also looked
  ahead past the requested date.
- Combining a datetime ``Factor`` with a numeric scalar raises the intended
  ``TypeError`` instead of a numpy ``ValueError``.
- ``fetch_csv`` raised ``AttributeError`` on CSV parse errors, and a fetched
  CSV with unknown sids raised an opaque ``TypeError``; the latter now raises
  ``SidsNotFound``.
- ``EyeLoader`` could not be constructed.
- ``RestrictedListOrder`` crashed on assets with NaT start or end dates.
- ``AssetDBWriter.write_direct`` crashed when given equities without
  exchanges; it now raises a ``ValueError``.
- Stock dividend payouts are read by column name, so they no longer depend on
  the column order in the adjustments database.
- ``run_algorithm`` and bundle ingestion no longer leak SQLite connections.

Maintenance and Refactorings
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

- Replaced unmaintained dependencies: ``trading_calendars`` with
  ``exchange_calendars``, ``empyrical`` with ``empyrical-reloaded``, ``bcolz``
  with ``bcolz-zipline``, ``python-interface`` with :mod:`abc`, ``pytz`` with
  :mod:`zoneinfo` in Zipline itself, and ``nose`` with ``pytest``. Removed
  ``six``, ``distutils`` and Python 2 compatibility code.
- Removed ``pandas.Panel`` and other APIs removed from pandas, numpy and Python.
- Removed the ``lru-dict``, ``multipledispatch`` and ``python-dateutil``
  dependencies, which the standard library, numpy and pandas cover.
- Ported the asset database to SQLAlchemy 2.
- Removed the unused ``zipline.utils.tradingcalendar`` and
  ``zipline.utils.data`` modules.

Build
~~~~~

- The project is built with ``pyproject.toml`` and managed with
  `uv <https://docs.astral.sh/uv/>`__. setuptools-scm replaces versioneer.
- Dropped the conda recipes, Travis, AppVeyor and Docker files.
- Continuous integration on GitHub Actions runs the tests on Linux and macOS
  with Python 3.12, 3.13 and 3.14, the doctests, ruff and ty.
- The optional ``talib`` extra uses the ``ta-lib`` package, which ships wheels
  that include the TA-Lib C library.

Documentation
~~~~~~~~~~~~~

- Updated the installation, development, trading calendar, data bundle,
  tutorial and release documentation for this release.
